# Organisation brain

Use the repository as the team's shared memory. Load the relevant reference for the requested job, do the work, and save changes that another teammate needs to continue.

## Locate the shared context

The repository root is three directories above this skill folder. Resolve the links below from this file, rather than assuming the current working directory. Read the root [AGENTS.md](../../../AGENTS.md) and [organisation context](../../../knowledge/organisation.md). For ongoing work, also read [active work](../../../operations/active-work.md).

## Choose the workflow

| Request | Reference and result |
| --- | --- |
| “Onboard me” or an organisation question | Read [event formats](../../../knowledge/events.md), [resources](../../../knowledge/resources.md), and relevant [open questions](../../../knowledge/open-questions.md). Give a short orientation or direct answer with source links; distinguish known facts from missing context. |
| “Organise these materials” or “process INBOX” | Follow [intake](../../../INBOX/README.md). Preserve originals, update the [source register](../../../sources/README.md) and affected guides, and report unresolved conflicts. |
| “Plan a workshop” | Read the [workshop playbook](../../../playbooks/workshops.md). Fill a copy of the [event brief](../../../templates/event-brief.md) under operations; record missing details as unconfirmed. |
| “Plan a Studio Session” | Read the [Studio Session playbook](../../../playbooks/studio-sessions.md) and use the same event brief. Keep its calendar, check-in, credits, and recap process distinct from workshops. |
| “Plan a showcase” | Read the [event formats](../../../knowledge/events.md) and [open questions](../../../knowledge/open-questions.md). Draft the brief, flag the missing showcase requirements, and seek those details instead of borrowing workshop rules. |
| “Continue work” or “leave a handoff” | Follow [work records](../../../operations/README.md). Read the actual task files, update active work with status, evidence, unknowns, owner if known, and the next action. Record actual lasting decisions in [decisions](../../../operations/decisions.md). |
| “Make event marketing materials” | Use the repo's [student-collective-marketing skill](../student-collective-marketing/SKILL.md) with the [marketing playbook](../../../playbooks/marketing.md). The supplied designs and brand instructions live with that skill. |

For other organisation questions, find the relevant guide and original evidence in the source register. Load supporting files as needed rather than reading every asset or source at startup.

## Finish with a usable result

Cite the relevant guide and original source for program requirements. Keep proposals distinct from approved plans and completed actions. Repository changes should leave a concise handoff with the files changed, unresolved questions, and next step. A read-only answer does not need a new work record.

Example: `$organisation-brain Plan our next Studio Session` should produce a draft brief grounded in the Studio Session source and ask for missing event details. It does not submit an event or issue credits.
